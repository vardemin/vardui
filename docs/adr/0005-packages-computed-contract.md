# ADR-0005: Пакеты с контрактом, вычисляемым компилятором

**Статус:** принято

**Контекст.** Зависимости в проектах VardUI добавляет в основном LLM-агент. В классических
менеджерах (npm, Cargo, pub, SwiftPM) пакет описывается заявлениями автора: версия, описание,
changelog. Для агента это значит: (1) угаданное имя может оказаться чужим пакетом
(slopsquatting), (2) semver и описание непроверяемы дешевле чтения кода, (3) что пакет делает
с устройством, не записано нигде, (4) обновление требует чтения changelog и ручной правки.
Отдельно: язык намеренно без импортов (ADR-0001), а пакеты вносят чужие имена.

**Решение.**
1. Пакет = код + **контракт, вычисляемый компилятором** (публичный API и возможности) +
   знание (AGENT.md ≤ 6 КБ, сгенерированный API, скиллы) + доказательство (headless-тесты при
   публикации) + миграции (`[[migrate]]` → `E0234` с `fix:`) + симуляция (`[sim]`).
2. Semver принудителен: реестр сравнивает API с предыдущей версией (`P015`).
3. Возможности (`secure permissions push native network prefs links share deeplinks`)
   вычисляются из кода; манифест обязан совпадать (`P013`); чувствительные одобряет человек в
   `[policy]` (`P008`); `vard.lock` их записывает.
4. Установка — только точные имена (`P001` с «did you mean»), реестр отсекает похожие имена
   (`P010`).
5. Пространства имён без импортов: своё → прямые зависимости → std; конфликт двух пакетов —
   `pkg.Name`; транзитивные невидимы; `_` — приватно; нативные имена глобальны. Компоновщик
   переименовывает конфликтующие объявления до проверки типов — рантайм о пакетах не знает.

**Последствия.** + агент знает API и риски пакета до установки, обновляет механически, не
может установить угаданное имя или выдать пакету неодобренные права; добавление пакета не
меняет смысл чужого кода. − пакетам нужен AGENT.md и пример с тестами; одна версия пакета на
приложение (как следствие общего пространства имён); возможности ограничивают «что», но не
«как» (одобренная `network` всё ещё может отправлять данные).
