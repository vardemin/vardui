# Архитектура VardUI

## Цели и их следствия

| Цель | Следствие в дизайне |
|---|---|
| ИИ пишет код с первого раза | маленький регулярный язык; синтаксис близок к Swift/Kotlin/TS, где у моделей сильные priors; одна форма на каждую вещь (`name: value`, без modifier-цепочек) |
| ошибки исправляются без размышлений | диагностика = `file:line` + строка кода + `fix:`; `vard check --fix` применяет исправления до неподвижной точки; таблицы «привычек» (`VStack→Column`, `onPress→onTap`, `var→state`, `"a"+n→"a{n}"`) |
| отладка без скриншотов | семантическое дерево с `@id`, диффы после действий, `why` для размеров, `state`, линты с готовым рецептом |
| минимум токенов | компактные форматы вывода; справочник генерируется из того же реестра, что и проверки; MCP-инструменты stateless — «сессия» = повторяемый список действий |
| производительность | fine-grained реактивность: тело вида выполняется один раз, дальше обновляется ровно тот prop, чьи зависимости изменились; layout за один проход |
| расширяемость | дизайн-системы = обычные виды на Vard (std так и написан); нативные функции = `extern fn`, события платформы = `extern event`; элементы = записи реестра |

## Слои

```
 .vard ──► vard-lang ──────────────────────────► vard-runtime ───────────────► платформа
           lexer → parser (arena AST,             reactive graph (signals,      headless: PNG (tiny-skia)
           error recovery) → checker              computed, effects, scopes)    [план] Android / iOS / Web /
           (bidirectional types, fixes)           retained Node tree            Desktop: GPU-рендер + нативные
           registry.rs — элементы, props,         flex layout + why-трассировка views для IME/карт/камеры
           токены, алиасы привычек                inspect: tree/layout/state/lint
                                                  actions: tap/type/scroll/expect
                         vard-cli: check · run · test · doc · explain · new · mcp
```

### vard-lang
- **Лексер** — переводы строк как разделители (кроме `(`/`[` и строк-продолжений `.x`, `&&`, `?`, `:`).
  Сразу ловит `;`, `===`, `@State` и т. п. с исправлением.
- **Парсер** — рекурсивный спуск, AST в плоских аренах (`ExprId`/`UiId` = `u32`), поэтому
  рантайм хранит в эффектах дешёвые индексы. Восстановление на уровне строки и
  объявления: за один прогон — максимум независимых ошибок; каскады «unknown name» после
  синтаксической ошибки подавляются.
- **Checker** — ожидаемый тип течёт вниз: `.center`, `.primary`, параметры лямбд выводятся без
  аннотаций. Тип `Unknown` после ошибки совместим со всем — нет лавины вторичных ошибок. Если
  исправление очевидно (алиас или расстояние Левенштейна), проверка продолжается так, будто оно
  уже применено, — одна итерация вместо нескольких.
- **registry.rs** — единственный источник правды: элементы, props и их типы, enum-ы, цветовые
  токены, шкала типографики, таблицы алиасов. Из него же генерируется `vard doc`.

### vard-runtime
- **Реактивность.** `state` → Signal, `let` и параметры вида → Computed (ленивые, с кэшем и
  автотрекингом), каждый динамический prop → Effect, пишущий одно поле одного узла;
  `if`/`for` → структурные эффекты. Владение — дерево `Scope`: удаление скоупа освобождает всё
  созданное внутри (эффекты, узлы, сигналы). Эффекты выполняются в порядке создания
  (родитель раньше ребёнка), что исключает «glitches».
- **Отсечения по равенству** на каждом уровне: сигнал не уведомляет при том же значении, prop не
  трогает узел при том же значении, неизменённые props не помечают layout грязным; статические
  props (литералы, enum, лямбды) вообще не создают эффектов.
- **Keyed `for`.** Реконсиляция по ключу `by`; у каждой строки свой сигнал значения, так что
  изменение одного элемента списка из 3000 перезапускает эффекты одной строки
  (замер: 7 действий над 3000 строками — 35 запусков эффектов).
- **Значения** — `Rc` + copy-on-write (`Rc::make_mut`): копирование бесплатно, мутация никогда
  не создаёт алиасов. Это делает семантику предсказуемой для модели.
- **Layout** — ограничения вниз, размеры вверх, один проход. Семантика CSS flex (`align`, `justify`,
  `grow`, `gap`). Каждый узел запоминает, *почему* получил размер по каждой оси — `why` печатает
  цепочку. Текстовые переносы кэшируются по (шрифт, ширина).
- **Инспекция** — семантическое дерево (контейнеры без смысла скрыты, метки сливаются как в
  accessibility), диффы, селекторы `@id` / `#id` / текст, линты, `state`.
- **Ошибки рантайма** не роняют приложение: любая проблема → `R`-диагностика с `file:line`, значение
  `nil`. Узлы из std-видов указывают на место использования вида в коде приложения.

### Нативный мост
- **Граница** — две декларации: `extern fn` (приложение → платформа) и `extern event`
  (платформа → приложение, обработчики `on name(...) [if cond] { }` живут, пока вид на экране).
  Через границу ходят только данные (структуры, enum, списки, map, optional) и колбэки
  `fn(T)` для результатов «потом»; checker запрещает остальное (`E0317`).
- **Формат** — JSON. Кодирование нетипизированное, декодирование — по *объявленному* в Vard
  типу (поля структур по имени, enum по имени варианта, умолчания для отсутствующих полей).
  Поэтому одна нативная функция обслуживает любые типы приложения: `firestoreGet*` в
  `vard-firebase` возвращает JSON-документ, а Vard превращает его в структуру `Profile`
  или `Note` — смотря как объявил разработчик.
- **Колбэки** — функции в аргументах превращаются в `{"$callback": id}`; хост отвечает
  `callback(id, json, keep)`. Замыкание, созданное внутри обработчика, «прикалывает» (pin)
  временные скоупы, которые захватило, — они переживают сам вызов до ответа платформы.
  Колбэк вида, который уже ушёл с экрана, тихо отбрасывается.
- **std-платформа** (`std.vard`): разрешения, `pref`/`prefGet`, `secure*` (Keychain/Keystore),
  пуши и уведомления, `setColorScheme`, `openUrl`, `haptic`, события `appear`/`back`/
  `appResume`/`appPause`/`deepLink`/`push*`, глобалы `safeArea`, `keyboardHeight`,
  `backProgress`, `isDark`, `screenWidth`.
- **Headless** — `Sim` в рантайме играет роль платформы детерминированно: настоящие
  in-memory prefs/secure, диалог разрешений отвечает то, что задал тест, пуши/back/insets
  вбрасываются действиями, `restart` моделирует холодный старт. Пользовательские extern
  отвечают `mock`-значением или висят в `pending` до `resolve`/`send`.
- **`pref`** — state, который рантайм сохраняет через ту же границу (`prefGet/prefSet` с
  ключом `vard.pref.<name>`), один сигнал на имя на всё приложение.
- **Edge-to-edge и back** — хост всегда рисует под системными барами и передаёт insets;
  `safeArea` добавляет их к padding. Если код ни разу не упоминает `safeArea`, рантайм
  отступает корень сам (статический флаг checker'а). `on back if cond` даёт хосту ответ на
  вопрос «перехватывает ли приложение back» (флаг в заголовке кадра) — от него зависит,
  покажет ли Android системную predictive-анимацию или отдаст прогресс жеста приложению.
- **Текст на устройстве** — ядро меряет платформенный шрифт через `TextMeasurer` хоста
  (Android `Paint.measureText`), шрифты проекта (`fonts/`) — тем же файлом через fontdue.
  Переносы строк и выравнивание на экране совпадают с тем, что считал layout.

### vard-cli и MCP
Тонкие команды над библиотеками. MCP-сервер (JSON-RPC по stdio) без состояния: `vard_run`
каждый раз монтирует приложение заново и проигрывает действия — 50–100 мс, детерминированно, нечему
«протухать» между вызовами.

## Модель отладки для ИИ

1. `vard check` → ошибки с исправлениями. 2. `vard run --do "tree"` → экран текстом.
3. Действия печатают только изменения. 4. `why`/`layout` дают числа и правило, создавшее размер.
5. Линты описывают проблему и рецепт. 6. Скриншот — только для оценки визуального дизайна.

## Дорожная карта

Текущая версия — эталонная реализация ядра и тулинга. Для production на устройствах:

1. **Нативные оболочки.** Ядро на Rust собирается как `cdylib`/`staticlib`; Android — Kotlin-хост
   (JNI), iOS — Swift-хост (C ABI). Рантайм выдаёт буфер команд мутаций дерева (create/set/insert/
   remove), хост применяет их за кадр.
   *Сделано:* `crates/vard-ffi` (C ABI + JNI) и `platforms/android` (библиотека `:vard` с
   `VardActivity`, приложение `:app`, модуль `:vard-firebase`). Хост получает кадр целиком —
   плоский список записей отрисовки (формат v2: тени, градиенты, радиусы по углам, шрифты,
   трансформации, `crates/vard-ffi/src/frame.rs`); hit-test и всплытие `onTap` остаются в ядре,
   `Input` — нативный `EditText` поверх Canvas. Буфер мутаций вместо полного кадра — следующий шаг.
2. **Рендер.** Основной путь — собственный GPU-рендер (wgpu/Skia-класс) поверх уже готового дерева и
   layout: пиксельно одинаковые произвольные дизайны и предсказуемая производительность. Нативные
   platform views встраиваются там, где важна интеграция: ввод текста с IME, карты, WebView, камера,
   видео. Шейпинг текста — HarfBuzz-класс с системными шрифтами.
3. **Исполнение.** AST-интерпретатор — dev-движок (мгновенный старт, hot reload). Для релиза —
   компиляция в компактный регистровый байткод или AOT в Rust; проверки типов уже статические, так
   что рантайм-проверки уходят.
4. **Нативные модули.** *Сделано:* `extern fn` с колбэками, `extern event` + `on`, std-платформа
   (разрешения, пуши, prefs, secure storage, back, insets), `vard bindings --kotlin`, модули-
   библиотеки с авто-регистрацией, Firebase. Дальше: генерация Swift, `async/await`-сахар над
   колбэками.
5. **Язык.** *Сделано:* `Map`, `pref`, `Grid`, wrap, тени/градиенты/шрифты. Дальше: навигация
   как встроенный элемент (сейчас — паттерн стек + `on back`), анимации
   (`animate:` на props — интерполяция в слое эффектов без перезапуска логики), жесты,
   виртуализация длинных списков, загрузка изображений, i18n, хранилище.
6. **Accessibility.** Семантическое дерево уже есть — маппинг на TalkBack/VoiceOver.
7. **Инспекция на устройстве.** Тот же протокол действий по WebSocket от устройства к `vard`: MCP-
   инструменты работают с реальным устройством без изменений.
